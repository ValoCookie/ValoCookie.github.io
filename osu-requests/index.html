osu!Requests

A Windows Twitch request manager and stream-side osu! toolkit for organizing beatmaps, driving OBS overlays, visualizing inputs and tap speed, showing current skins and keeping Ranked Play information live.

Request management

Viewer requests without the copy-paste circus.

Turn Twitch beatmap links into an organized queue with map data, request rules and controls built for the streamer.

Queue & review

Open or close requests, set queue and per-viewer limits, review maps before they enter the active queue and keep session history.

Optional map filters

Set Min/Max limits for PP, stars, length, BPM, AR, CS and OD, plus status and mode restrictions—or leave filters blank when you do not want them.

Requested mods

Requested mods stay attached to the map. When the request is delivered in osu! chat, NoMod stays clean with no NM label, while modded requests show only the actual mods such as HD, DT or HDDT—without the old Suggested prefix.

Reply / @mention safe

Beatmap links are still recognized when Twitch prepends a reply mention or invisible formatting, while the actual sender remains the requester.

Personal queue — !myq

Viewers can check their own active requests, queue usage and how many more maps they can submit under the current limits.

Queue history

Opened requests stay available in History so older maps can be revisited without corrupting the active queue.

Now Playing

Keep chat synced with what is actually selected.

The current-map system is not limited to maps opened from the request queue.

!np

Chat can request the current / most recently selected map, with difficulty, stars, requested mods and the map link when available.

Song Select support

osu!stable selection and preview events can update !np before gameplay starts, including maps manually selected outside the queue.

Startup restore

A bounded recent-log scan can restore the newest known selection when osu! is already running before osu!Requests launches.

Current Skin

Tell chat which skin is actually active.

Stable and lazer are handled separately, with conservative name detection so the app does not invent a custom skin name.

Dual-client !skin

Report the selected osu!stable and/or osu!lazer skin in one response and automatically mark a detected running client.

Editable names & links

Keep automatic detection or override the chat-facing name and attach an HTTP/HTTPS skin link independently for stable and lazer.

Broadcaster !setskin

Change a display name or link from Twitch chat, return to automatic detection with auto, or clear an override without editing Python.

Accurate custom lazer names

Uses exact metadata pairs, verified local data or optional tosu v2 integration. If a name cannot be proven, it simply reports Custom skin.

Skin source controls

Choose whether stable, lazer or both appear in !skin, open the selected stable skin folder, and open lazer storage from Preferences.

Manual lazer fallback

Name the current lazer skin once for a specific GUID when that local Realm layout cannot be resolved safely.

OBS request overlays

Use only the stream elements you want.

Request information is exposed as separate local Browser Sources so each element can be positioned and styled independently.

Current Map

Show the current requested / selected map information as its own Browser Source.

Compact Queue

Keep upcoming requests visible without giving the queue an entire scene.

Requests Open

Expose the current request-open status separately so it can live wherever it fits your layout.

Key Visualizer

Inputs, trails and real tap speed in one overlay.

Run the visualizer as its own OBS Browser Source with background capture and flexible stream-oriented layouts.

60 FPS overlay

The browser overlay targets roughly 60 frames per second for smoother press feedback and trails.

Independent inputs

Configure Key 1, Key 2 and optional mouse inputs with independent press colors and separate K1/K2 trail colors.

Live BPM

A dedicated speed card measures recent input timing with no artificial BPM ceiling, so very fast 300–400+ BPM tapping can still be represented.

Consistency-aware MAX BPM

During a stable stream the card shows live BPM; when tapping becomes uneven or stops it falls back to the fastest consistency-qualified MAX BPM for the session.

Correct dual-input speed

Configured inputs are measured independently and combined so simultaneous two-button tapping is not incorrectly shown as half-speed.

Horizontal or vertical

Choose horizontal / vertical layouts and Up / Left / Right trail directions for compact strips or classic vertical stacks.

Cumulative TOTAL

Total key presses remain cumulative until you deliberately reset them instead of resetting every second.

Custom color picker

Use the dark in-app picker, editable HEX values, RGB/HSV controls and recent-color swatches across overlay colors.

Background capture

Supported keyboard, punctuation, modifier and mouse bindings continue to update while the desktop app is minimized.

Ranked Play

Profile stats and match changes without another utility.

The Ranked Play Tracker now keeps official profile information visible outside a match and switches into a much faster live refresh while the overlay is in use.

Profile snapshot anytime

Opening the tracker or pressing Refresh Now requests the official Ranked profile snapshot even when background tracking is disabled.

Ranked profile cards

Show leaderboard rank, rating, games, wins, win rate, lifetime Ranked wins and season score where the official data is available.

~1.5 second live mode

When the Ranked OBS source or preview is visible, it requests a fresh snapshot about every 1.5 seconds and bypasses the small relay profile cache.

Transparent OBS mode

Remove the ranked card fill, border and shadow while keeping text, rating, graph, points and labels visible over your stream.

Custom appearance

Line, win, loss, background, text colors and opacity stay editable; background and opacity are ignored while transparent mode is enabled.

Session graph

Session delta and W/L remain session values and update when osu!'s published Ranked Play statistics actually change.

Updates & reliability

Fewer manual downloads and fewer mystery states.

Update discovery uses multiple sources and packaged builds can replace the installed portable EXE automatically.

Multiple update sources

Checks the ValoCookie update manifest and GitHub release information, choosing the highest valid semantic version when one source is stale.

UPDATE NOW

The packaged Windows build stages the replacement in Windows TEMP, waits for the old process to exit, backs up and verifies the portable EXE, replaces the exact running OsuRequests.exe path and relaunches that same file.

Verified replacement

The updater checks file size and SHA-256 before relaunching. Update diagnostics are written under Windows TEMP instead of leaving update copies beside the installed app.

Common questions

Quick answers.

Does the Key Visualizer work while the app is minimized?

Yes. Supported keyboard and mouse bindings are captured in the background for the Browser Source.

Is tap speed capped?

No artificial BPM maximum is configured. The displayed value is derived from the measured input timing, with a consistency-qualified MAX BPM record for sustained tapping.

Can !skin include a download link?

Yes. Stable and lazer can each keep automatic detection or use an editable display name and HTTP/HTTPS link.

Does Ranked Play update outside an active match?

Yes. Profile data can refresh outside a match, and the overlay / preview uses the faster live refresh mode while visible.

Does UPDATE NOW create another permanent EXE?

No. The replacement is staged in Windows TEMP and the exact installed portable EXE path is swapped during one brief automatic restart.
